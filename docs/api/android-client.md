# Android 阅读器接入

## 登录与文件关联

1. 通过 `POST /api/v1/auth/device-login` 登录，安全保存返回的 `accessToken`。向受保护接口发送 `Authorization: Bearer <token>`，使用独立于 Web Cookie 的客户端。收到 401 时重新登录，保留离线队列和已保存的同步设备 UUID。
2. 从 Android 文件选择器读取字节流并计算 SHA-256。通过 `GET /api/v1/files/matches?sha256=<hex>` 查找候选，可用 `bookId` 限定到用户已选的书目。继续按 `nextOffset` 分页，直到返回 `null`。
3. 将用户选定的服务器 `bookId`、`bookFileId` 和本地 SHA-256 与文件 URI 一起保存在客户端数据库。多条候选需让用户选择，即使文件字节完全相同也可能属于不同书目。打开本地文件时校验它仍是关联版本。若服务端文件的哈希改变或同步收到文件墓碑，标记关联待确认。索引状态为 `missing` 的文件仍可匹配本地副本。
4. 未匹配时，可用现有书目 API 选择或创建书目，再提交 `POST /api/v1/uploads?reuseExisting=true`。新文件返回 201，同书已有相同内容且索引为可用时返回 200。两者都返回可用于关联的稳定文件 ID。跨书同哈希仍允许各自关联。

## 下载与校验

- 从文件内容接口下载到临时文件。保存返回的强 `ETag`，断点续传时发送 `Range: bytes=<已下载字节数>-` 和 `If-Range: <ETag>`。收到 206 时，核对 `Content-Range` 起点、总长度与验证器再追加；收到 200 时从头替换临时文件。
- 若响应只有弱 ETag，无法按版本续传。收到 416 时核对返回总长度，只有临时文件大小与预期哈希同时正确才视为完成，否则重新下载。
- 完整下载后检验最终字节数和 SHA-256，优先使用下载响应的 `X-Content-SHA256`。该头缺失时，可用本地已选定版本的已知哈希验证。若没有可信的预期哈希，等待服务端重新扫描生成哈希后再确认文件完整性。通过校验后再发布到离线库。[文件 API](files.md)

## 同步阅读数据

- 首次连接按[同步 API](sync.md)分页拉取快照并追赶增量，之后保存游标。应用文件变更时保留本地文件 URI 来自客户端的关联信息。
- 阅读位置以 `bookFileId` 为键。会话、书签和划线笔记使用稳定 ID，并提供关联的 `bookId` 和适用的 `bookFileId`。离线变更持久化 `mutationId` 和同步外层 `baseRevision`，网络恢复后按顺序批量提交。
- 重试时沿用原变更 ID。收到版本冲突时以回执的服务器当前记录或删除墓碑为依据进行处理，解决后用新的变更 ID 提交。直接使用 Reader API 保存位置时，使用该记录内部的 `revision`。[阅读数据 API](reader.md)
