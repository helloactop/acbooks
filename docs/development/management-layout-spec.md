# acbooks Web 管理面板布局与 AppShell 设计规范

> 状态：待实现，供开发 AI 直接执行。  
> 适用范围：Web / Windows 共用 Web UI；桌面横屏、平板、手机竖屏及手机横屏。原生 Android 不在本次实现范围。  
> 参考项目：二猫书库 ermao-library，main 提交 `21b5715e884fda4375c2621b96f0751f4d542703`。  
> acbooks 分析基线：main 提交 `4778d5703ea5b777efdf02925e29c0e311d95895`。开发前重新确认当前分支和最新源码，不回退并行开发成果。  
> 配套文档：`acbooks-book-detail-spec.md`（图书详情页专项规范）。

## 1. 任务目标

借鉴二猫书库的全局导航、信息架构、首页、书库和设置中心布局，将 acbooks 当前仅由书库页面使用的 AppShell 升级为统一的已登录应用框架。

**借鉴二猫的布局与交互，保留 acbooks 的蓝色主题、圆角主内容面板、语义设计令牌和现有公共组件。不要照搬二猫的暖色背景、橙色按钮、书架木纹或业务模型。**

开发前阅读 `AGENTS.md`、`docs/architecture/system.md`、`docs/development/standards.md`、`docs/development/ui.md`、`docs/development/ui-components.md`、`docs/development/ui-pages.md`、`docs/api/books.md`，涉及接口时同时阅读 API、后端、安全及测试规范。仓库权威规范优先；本文新增的结构、尺寸和交互是建议实施方案。如有冲突，先报告并明确解决方式，不擅自改写全局设计系统。

本次核心交付是 **共享 AppShell、可用的响应式导航、统一全局搜索、账户入口、页面级布局和现有书库功能迁移**。首页、书架、设置等新功能依据真实 API 分阶段开放；不得伪造数据或构造虚假业务流程。

### 4.2 建议实施尺寸（CSS px）

| 部位 | 规范 |
| --- | --- |
| 外壳 | `height:100dvh`，flex；背景使用 `frame`，不锁定浏览器缩放 |
| 完整侧栏 | `clamp(236px,16vw,264px)`；左右内边距 16；不随主内容滚动 |
| 侧栏顶部 | Logo 32×32，品牌文字使用现有字号；品牌区约 56 高；搜索框 40 高 |
| 导航项 | 桌面 40 高，移动触控至少 44×44；图标 18–20，图文间距 8–12，圆角用 control |
| 导航分组 | 组标题 12–13，组间距 20–24；动态区独立纵向滚动 |
| 账户区 | 底部固定，顶部细分隔线，头像 36–40；整行可操作；长名称截断 |
| 主面板 | 复用 `rounded-panel` / background；建议外边距 8（顶部、右侧、底部），不增加额外包裹层 |
| 主内容 | 桌面内边距 24；极宽屏可按令牌增至 32；默认 gap 24；`min-width:0; min-height:0` |
| 内容宽度 | 普通书库、首页、详情建议最大 1280 并居中；密集列表可按业务扩展；设置表单建议 960 上限 |
| PageHeader | 标题沿用当前约 28px 语义标题；标题、数量/说明与主操作清晰对齐；允许换行 |

不使用固定像素宽度挤压内容，不使用 `width:100vw` 造成滚动条溢出。主内容区为唯一主要纵向滚动容器；侧栏长列表可独立滚动，弹窗内部滚动属于例外。滚动恢复由 `layout/scroll-restoration.ts` 统一管理：新页面导航与分页回到顶部，详情返回恢复进入详情前的位置，浏览器前进/后退按历史条目恢复。

## 5. 横屏、竖屏及响应式规范

以 CSS 视口宽度和实际内容可用宽度为依据，而不是仅判断设备型号或屏幕方向。下列断点为 acbooks 适配建议；参考二猫的 1024px 主断点。

| 视口宽度 | 全局导航 | 主内容区 |
| --- | --- | --- |
| ≥1280 | 完整侧栏 | 圆角面板，24–32 内边距；宽内容布局 |
| 1024–1279 | 完整侧栏 | 24 内边距；业务内容根据剩余宽度由多栏降为两栏或单栏 |
| 768–1023 | 抽屉，默认关闭 | 内容占满宽度；20–24 内边距；可两栏 |
| 640–767 | 抽屉，默认关闭 | 16–20 内边距；按内容空间重排 |
| <640 | 抽屉，默认关闭 | 16 内边距；单列优先；不保留桌面外边距和大圆角 |

### 5.1 手机竖屏

```text
┌───────────────────────────┐
│ ☰  全部书籍        ＋     │  页面标题与主操作
│ 128 本                    │
│ [全部 未读 在读 已读]    │  快捷状态
│ [筛选] [排序] [网格/列表] │  可换行
│ ───────────────────────── │
│ ┌────────┐ ┌────────┐     │
│ │ 封面   │ │ 封面   │     │
│ └────────┘ └────────┘     │
│  书名       书名          │
│  作者       作者          │
│                           │
│          …                │
└───────────────────────────┘
```

- 左上角导航按钮由 AppShell 提供能力，在统一 PageHeader 中显示。不得同时出现全局菜单与重复页面菜单。
- 搜索与账户位于导航抽屉；书库内部搜索属于当前书库工具栏，可折行显示，不是第二个全局搜索框。
- 两列书籍网格沿用已有设计；极窄屏、200% 缩放或长文本允许减至一列。列表列数按优先级减少，书名及关键操作始终可见。
- 不强制新增底部 TabBar，避免与抽屉重复。适配 `env(safe-area-inset-*)`、浏览器地址栏与软键盘；交互目标至少 44×44。

### 5.2 平板与手机横屏

- 平板横屏实际宽度达到 1024 才出现固定侧栏；平板竖屏一般使用抽屉。
- 手机横屏如 844×390、667×375：仍使用抽屉；页面操作允许换行，主内容纵向可滚动，不强制显示桌面三栏。
- 低高度视口中导航抽屉顶部/底部固定、中部滚动；菜单、表单与弹窗不超出视口，保存与关闭按钮可达。禁止将全部页面锁定为不可滚动。
- 旋转屏幕或调整窗口时不清空查询、分页、编辑草稿与阅读/详情分页；跨断点时清理不再适用的抽屉遮罩、焦点锁定和历史状态。

### 5.3 移动导航抽屉

- 从左侧滑入，宽 `min(82vw,320px)`；遮罩使用现有 overlay 令牌；不硬编码二猫的暖色。
- 复用桌面导航数据和账户操作，避免两套业务状态；包含 Logo、关闭按钮、全局搜索、导航分组、底部账户区。
- 点击菜单项后关闭并进入目标页面；点击遮罩、关闭按钮、Escape 或浏览器返回键可关闭；如使用滑动关闭，不与垂直滚动冲突。
- 打开时锁定背景滚动，背景不可聚焦，焦点进入抽屉并循环；关闭后回到触发按钮或目标页面合理焦点位置。优先使用现有/按规范实现的 Radix Dialog 或 Drawer。
- 使用设计令牌中已有抽屉动画时长（参考 240ms），尊重 `prefers-reduced-motion`。动画仅作用于 transform/opacity 等需要变化的属性。
- 关闭状态不得存在可点击的透明覆盖层；打开抽屉使用一个由 React Router 管理的同址历史条目（`acbooksDrawer` 状态），抽屉内导航以 replace 复用该条目，不残留重复历史；进入桌面布局后立即清理抽屉状态。

## 6. 导航信息架构

以下为目标结构，首版只开放已具备真实页面/API 的导航；后续功能保留配置位置而不是提供无效跳转。

```text
正常模式
├─ 首页
├─ 书库
│  ├─ 全部书籍
│  ├─ 实体书
│  └─ 电子书
├─ 我的书架
│  ├─ 动态书架（按后端返回）
│  └─ 新建书架
├─ 阅读
│  ├─ 阅读记录
│  └─ 阅读统计
└─ 账户与设置（底部固定）
```

- 首页与书库为不同场景；实体书、电子书是同一个 Book 列表的不同过滤视图，而不是两套数据库、列表组件或书籍详情。一本书同时拥有实体与电子资源时可出现在两种视图，但全部书籍只出现一次。
- `mediaType=physical/digital` 表示当前 API 中存在相应副本/文件，未绑定资源的书目仍出现在全部书籍；不要将其擅自判为实体书。
- 动态书架以稳定 ID 为 key 和路由参数；需要真实书架列表 API 后才启用。当前 API 仅返回书架名称的地方不得自行制造 UUID。普通书架优先；智能书架及合集待支持真实规则模型后再开发。
- 不在正常导航里重复放置存储、任务、备份、系统日志、OPDS 等后台入口；统一放在设置模式。
- 当前页使用语义选中色、`aria-current` 与清晰文字；路由和查询参数是选中状态来源。悬停、选中、禁用和焦点要有区分；图标使用 Lucide 并提供可访问名称。
- 长书架名允许截断并展示完整名称；动态区域多项时纵向滚动，底部账户不被推出视口。

## 7. 全局搜索

侧栏搜索用于查询整个图书库，当前页面搜索/筛选仅用于当前书库上下文，不能共用一个易混淆的过滤状态。

- 桌面位置：品牌下方；手机位置：抽屉内。显示 Search 图标、输入框和可用的快捷键提示。
- 支持 `Ctrl+K` / `Cmd+K` 聚焦，移动端快捷键触发时先打开抽屉再聚焦；设置模式默认不展示搜索，可在返回阅读后使用。
- 使用现有 `GET /api/v1/books?q=...&limit=5&offset=0` 进行全库预览；按当前 API 支持的书名、作者/译者、ISBN 搜索，不承诺尚未支持的标签全文查询。
- 输入防抖建议 250ms；保留现有中文输入法 composition 处理。请求取消或序列校验，旧查询结果不可覆盖新查询；空关键词关闭结果，不拉取全库。
- 下拉显示最多 5 本真实书籍：小封面、书名、作者；缺失封面使用现有 BookCover/占位；底部显示全部结果入口和真实总数。
- ↑/↓ 选择、Enter 打开当前结果或全部结果、Escape 关闭结果、点击外部关闭。键盘焦点及下拉位置在侧栏滚动时仍正确，Portal/层级不得裁切。
- 点击结果进入真实详情路由；点击全部结果进入书库并携带 `q`。从详情返回时恢复来源上下文。网络失败显示重试，不伪装成无匹配结果。

- PageHeader 提供页面标题和添加书籍主操作；添加行为复用书库中已有真实创建表单及刷新逻辑。
- 继续阅读卡片：桌面横向封面/信息/操作三段；封面建议 150×225，窄屏纵向或紧凑双段。进度、位置及继续阅读目标必须来自真实阅读数据，不从书名、阅读状态或样例推断。

- 真实空书库显示添加第一本书的入口，加载与失败独立处理。不要引入木纹书架或额外装饰材质。
- 阅读时长、年度目标、趋势图放入后续阅读统计模块；系统健康、任务和日志放入设置/管理页面。

## 9. 书库、书架与详情页面模板

### 9.1 书库

- 采用共享 AppShell + PageHeader（标题、真实数量、Soft 添加按钮）+ LibraryToolbar + 图书内容 + Pagination。
- 保留当前真实创建、查询、编辑、分页、会话失效处理；保留网格和列表，二者共用相同查询条件与结果。
- 阅读状态使用现有 SegmentedControl（全部/未读/在读/已读）；更多筛选采用 SlidersHorizontal、激活样式和条件计数；排序与视图切换单独保留。展开筛选区位于工具栏下方，不使用遮挡列表的复杂模态框。
- 现有固定查询参数可实现类型、状态、标签、书架（真实 ID）、格式、排序等。完整 AND/OR、任意字段和运算符需要后端契约扩展；未支持时使用简单筛选面板，禁止仅过滤当前分页并伪称全库筛选。
- 页面查询、筛选、排序、分页和视图状态可通过 URL 或现有导航状态恢复；修改筛选后回到第一页，取消过期请求。现有服务端数据保持唯一事实来源。

### 9.2 书架

- 首版普通书架：名称、简介（若模型/API 支持）、真实书籍数量和图书集合。可使用同一个书库内容组件，不另造书目模型。
- 书架管理、创建及编辑复用真实书架接口和表单；待 API 开放后实施。
- 后续智能书架复用经过后端验证的组合筛选模型；合集、自动归类不属于 AppShell 改造任务。

### 9.3 书籍详情

- 使用 `acbooks-book-detail-spec.md` 作为详情专项规范。详情页与书库共享 AppShell，优先独立路由，书目身份始终为真实 `bookId`。
- 宽内容区封面/信息/操作三栏；中等内容区两栏；手机竖屏纵向布局。断点应根据主内容实际可用宽度，不能简单按全屏宽度套三栏。
- 保留书库来源查询及滚动上下文。此次外壳规范将全局搜索和账户迁移到侧栏，专项规范中提到的“顶部导航”按新 AppShell 实际结构适配，其他详情内容规则保持不变。
- 详情页已迁移为独立详情路由，本次只调整外壳；必须确保编辑、阅读状态与错误处理不回退；添加和编辑仍可使用 Dialog。

## 11. 账户、认证与页面路由

- 将当前右上角账户菜单移至底部账户区域；主入口进入设置，提供明确的退出登录入口（账户菜单或账户设置页），不将整个头像只变成装饰。
- 复用已实现的 session check、CSRF Token、Cookie、退出 API。将会话与统一失效处理提升到已登录框架或共享 AuthGate；避免每个业务页面重新发起独立认证流程。
- 登录/初始化页、独立开发预览页不嵌入业务 AppShell。后续阅读器等沉浸页面根据需求独立处理，不在本次开发假阅读器。
- 401 会话失效进入登录；403、网络异常及服务端错误按实际语义处理，不把所有异常视为登出。退出成功清理账户关联页面状态和请求，失败显示真实错误；不在 localStorage 保存密码、Cookie 或 CSRF Token。
- 参考路由：`/`（已登录首页；若现有登录流程依赖根路径，先明确迁移）、`/library`、`/library/:bookId`（与详情专项规范及已有路由兼容）、`/shelves`、`/reading/history`、`/reading/statistics`、`/settings` 及其子路由。此清单是目标，不代表全部页面已存在；登录/初始化入口继续遵循当前实现，必要时同步修正跳转及测试。
- 固定导航按真实路由激活；详情进入时书库来源高亮合理；未知路由显示安全的未找到状态或规范回退，不将错误路径当成登录页。

## 13. 开发顺序与范围

1. 确认并行任务及 Git 基线，先明确 AppShell、路由和详情规范之间的边界；保留当前已提交和工作区业务成果。
2. 提升共享已登录 AppShell，统一页面容器、PageHeader、正常/设置导航结构；迁移现有书库，不改变业务逻辑。
3. 实现可用移动抽屉、全局搜索、账户与退出；完成键盘和会话状态处理。
4. 将真实书库、详情页及添加/编辑弹窗接入；按真实 API 调整筛选，确保所有已有功能不回退。
5. 在已有 API 范围内增加首页最近加入、个人主题与语言设置；后续阅读、动态书架、系统设置在独立任务实现对应 API 后再开启。
6. 完成响应式、主题、语言、可访问性和回归测试，提供实际截图与变更报告。

本次不要求开发完整阅读器、阅读同步、书架 CRUD、智能筛选后端、上传扫描、元数据刮削、多用户权限、PWA、OPDS 等。若用户明确授权这些功能，另行设计接口与验收，不混入布局重构。

### 14.2 功能与回归

- 登录、会话恢复、退出、401 失效和非认证错误行为不回退；不暴露受保护内容。

- 抽屉可打开、关闭、键盘退出、点击遮罩关闭、返回键关闭；切换断点后无遮罩残留和焦点锁定。

- 主题和语言切换不重置业务上下文；长名称、动态导航大量条目及窄窗口不破坏框架。
