# acbooks Web 管理面板布局与 AppShell 设计规范

> 状态：已实现（2026-11-13，B 方案：80px 图标轨 + 56px 顶栏 + 移动抽屉）。
> 适用范围：Web / Windows 共用 Web UI；桌面横屏、平板、手机竖屏及手机横屏。原生 Android 不在本次实现范围。
> 参考项目：二猫书库 ermao-library，main 提交 `21b5715e884fda4375c2621b96f0751f4d542703`。
> acbooks 分析基线：main 提交 `4778d5703ea5b777efdf02925e29c0e311d95895`；当前实现已迁移至 React Router 持久化 AppShell，布局以本文第 4–7 节为准。
> 配套文档：`acbooks-book-detail-spec.md`（图书详情页专项规范）。

## 1. 任务目标

借鉴二猫书库的全局导航、信息架构、首页、书库和设置中心布局，将 acbooks 当前仅由书库页面使用的 AppShell 升级为统一的已登录应用框架。

**借鉴二猫的布局与交互，保留 acbooks 的蓝色主题、圆角主内容面板、语义设计令牌和现有公共组件。不要照搬二猫的暖色背景、橙色按钮、书架木纹或业务模型。**

开发前阅读 `AGENTS.md`、`docs/architecture/system.md`、`docs/development/standards.md`、`docs/development/ui.md`、`docs/development/ui-components.md`、`docs/development/ui-pages.md`、`docs/api/books.md`，涉及接口时同时阅读 API、后端、安全及测试规范。仓库权威规范优先；本文新增的结构、尺寸和交互是建议实施方案。如有冲突，先报告并明确解决方式，不擅自改写全局设计系统。

本次核心交付是 **共享 AppShell、可用的响应式导航、统一全局搜索、账户入口、页面级布局和现有书库功能迁移**。首页、书架、设置等新功能依据真实 API 分阶段开放；不得伪造数据或构造虚假业务流程。

## 4. 全局 AppShell 桌面布局

### 4.1 布局结构

```text
┌──────┬──────────────────────────────────────────────────────────────┐
│ 品牌 │  [ 全局搜索                      ⌘K ]              [账户]    │  56px 顶栏
├──────┼──────────────────────────────────────────────────────────────┤
│ 首页 │  PageHeader（标题 / 计数或说明 / 主操作）                    │
│      │                                                              │
│ 图书 │  页内分段（全部书籍 / 实体书 / 电子书）                      │
│ 库   │  状态 ▾   排序 ▾                         [筛选] [视图] [⋯]   │
│      │  当前搜索标签（有 q 时） → 内联高级筛选（按需）              │
│      │  书籍网格 / 列表 → 分页                                      │
└──────┴──────────────────────────────────────────────────────────────┘
  80px
```

示意仅描述结构，真实页面只展示已经开放的入口。全局搜索只在顶栏出现一次；书库页内不再放置第二个搜索框。

### 4.2 建议实施尺寸（CSS px）

| 部位 | 规范 |
| --- | --- |
| 外壳 | `height:100dvh`，flex；框架（图标轨、顶栏、页面外围）使用 `frame`，主内容使用 `background`；不锁定浏览器缩放 |
| 图标轨 | 宽 80；品牌 28–36；一级导航为图标 20 + 10px 名称，项宽约 64–72，圆角 `control`；选中使用 `accent-soft` + `accent-text`；与主内容之间不画分割线 |
| 顶栏 | 高 56，水平内边距 16；不画底部分割线，与图标轨同用 `frame`；搜索最大宽 420、控件高 32（<lg 44）；账户入口（头像 + 昵称）右对齐，点击进入设置；不设独立退出/设置按钮 |
| 主内容 | 所有断点为 `background` 圆角面板，四周留 8，浮于 `frame` 之上；唯一主要纵向滚动容器；<768px 内边距 8（视觉外边距 16），≥768px 水平 20；页面区块间距 16；隐藏可视滚动条但保留滚动 |
| 内容宽度 | 书库与详情不强制居中限宽，按可用宽度铺开；首页建议 1200、设置 960 居中 |
| PageHeader | 标题 22/600，说明 13，间距 4；操作区尾部对齐，窄屏允许换行；每个操作区最多一个 Soft 主操作 |

主内容区为唯一主要纵向滚动容器；图标轨和顶栏不随内容滚动，弹窗内部滚动属于例外。滚动恢复由 `layout/scroll-restoration.ts` 统一管理：新页面导航与分页回到顶部，详情返回恢复进入详情前的位置，浏览器前进/后退按历史条目恢复。

## 5. 横屏、竖屏及响应式规范

以 CSS 视口宽度和实际内容可用宽度为依据，而不是仅判断设备型号或屏幕方向。本实现以 768px 作为图标轨与抽屉的切换断点，低于二猫的 1024px 主断点。

| 视口宽度 | 全局导航 | 主内容区 |
| --- | --- | --- |
| ≥1280 | 80px 图标轨 + 56px 顶栏 | 内容铺满；内边距 20；书库控件单行 |
| 1024–1279 | 80px 图标轨 + 56px 顶栏 | 内边距 20；书库分段与控件单行 |
| 768–1023 | 80px 图标轨 + 56px 顶栏 | 内边距 20；书库媒体分段单独一行，状态/排序与工具栏一行 |
| 480–767 | 抽屉，标题行内菜单触发 | 卡片内边距 8（视觉外边距 16）；媒体分段整行；状态/排序整行；筛选/视图/更多右对齐 |
| <480 | 抽屉 | 卡片内边距 8（视觉外边距 16）；网格 1–2 列，控件仍保持整齐分组 |

### 5.1 手机竖屏

```text
┌───────────────────────────┐
│ ☰  书库            ＋     │  页面标题与主操作（PageHeader）
│ 共 128 本                 │
│ [全部书籍 实体书 电子书]  │  页内媒体分段
│ [全部 ▾] [最近添加 ▾]     │  状态 / 排序
│           [筛选] [视图] [⋯]│  紧凑工具栏
│ ───────────────────────── │
│ ┌────────┐ ┌────────┐     │
│ │ 封面   │ │ 封面   │     │
│ └────────┘ └────────┘     │
│  书名       书名          │
│  作者       作者          │
└───────────────────────────┘
```

- 左上角菜单按钮由 `PageHeader` 渲染，仅在 <768px 出现；点击打开抽屉，不与常驻图标轨重复。
- 全局搜索与账户位于抽屉内，顶栏搜索在 <768px 隐藏；书库页内不保留搜索框。带 `q` 进入书库时，计数旁显示可清除的查询标签。
- 媒体分段在窄屏占满整行、三个选项等宽；状态和排序各占一半；筛选/视图/更多作为一组右对齐，不拆成孤立的单个按钮。
- 列表列数按优先级减少，书名及关键操作始终可见；不强制新增底部 TabBar。适配 `env(safe-area-inset-*)`、浏览器地址栏与软键盘；交互目标至少 44×44。

### 5.2 平板与手机横屏

- 宽度达到 768 即显示 80px 图标轨与 56px 顶栏；低于 768 使用抽屉。
- 手机横屏如 844×390、667×375：仍使用抽屉；书库控件按 5.1 整行分组，主内容纵向可滚动。
- 低高度视口中导航抽屉顶部/底部固定、中部滚动；菜单、表单与弹窗不超出视口，保存与关闭按钮可达。禁止将全部页面锁定为不可滚动。
- 旋转屏幕或调整窗口时不清空查询、分页、编辑草稿与阅读/详情分页；跨断点时清理不再适用的抽屉遮罩、焦点锁定和历史状态。

### 5.3 移动导航抽屉

- 从左侧滑入，宽 `min(82vw,280px)`；遮罩使用现有 overlay 令牌。
- 竖屏支持手势：从屏幕左边缘（约 28px 内）向右滑打开抽屉，在抽屉内向左滑关闭；水平位移至少 56px 且明显大于垂直位移，垂直滚动不触发，表单输入区域不触发关闭，避免与文本选择冲突。
- 抽屉内容依次为品牌与关闭、全局搜索、一级导航（首页、图书库）、底部账户入口（头像 + 昵称，点击进入设置）；与桌面图标轨/顶栏共用同一导航配置。
- 点击菜单项后关闭并进入目标页面；点击遮罩、关闭按钮、Escape 或浏览器返回键可关闭。
- 打开时锁定背景滚动，背景不可聚焦，焦点进入抽屉并循环；关闭后回到触发按钮或目标页面合理焦点位置。优先使用现有/按规范实现的 Radix Dialog 或 Drawer。
- 使用设计令牌中已有抽屉动画时长（240ms），尊重 `prefers-reduced-motion`。动画仅作用于 transform/opacity 等需要变化的属性。
- 关闭状态不得存在可点击的透明覆盖层；打开抽屉使用一个由 React Router 管理的同址历史条目（`acbooksDrawer` 状态），抽屉内导航以 replace 复用该条目，不残留重复历史；进入 ≥768px 布局后立即清理抽屉状态。

## 6. 导航信息架构

以下为目标结构，首版只开放已具备真实页面/API 的导航；后续功能保留配置位置而不是提供无效跳转。

```text
图标轨
├─ 首页
├─ 图书库
│   └─ 页内分段：全部书籍 / 实体书 / 电子书
└─ （账户入口）设置（账户分组内含退出登录）

移动抽屉
├─ 首页
├─ 图书库
└─ 账户入口 → 设置（底部；退出登录在设置页）
```

- 首页与书库为不同场景；实体书、电子书是同一个 Book 列表的不同过滤视图，以书库页内的分段控件切换，不占用一级导航、不拆成两套数据库、列表组件或书籍详情。
- `mediaType=physical/digital` 表示当前 API 中存在相应副本/文件，未绑定资源的书目仍出现在全部书籍；不要将其擅自判为实体书。
- 动态书架以稳定 ID 为 key 和路由参数；需要真实书架列表 API 后才启用。当前 API 仅返回书架名称的地方不得自行制造 UUID。普通书架优先；智能书架及合集待支持真实规则模型后再开发。
- 未实现的阅读、书架、存储、任务等入口不显示禁用占位；后续开放时再评估是否进入图标轨或设置。设置与账户当前由顶栏账户入口进入，不另造一级导航。
- 当前路由使用 `aria-current` 与淡色背景；图标轨选中态同时改变图标和文字颜色。悬停、选中、禁用和焦点要有区分；纯图标控件必须有双语可访问名称。
- 长用户名在顶栏截断并保留完整可访问名称；移动抽屉底部账户区不被推出视口。

## 7. 全局搜索

全局搜索只用于查询整个图书库；书库页内不再另设搜索框，避免两个输入框写入同一查询状态。

- 桌面位置：56px 顶栏左侧（最大宽 420）；移动位置：抽屉顶部。显示 Search 图标、输入框和快捷键提示。
- 支持 `Ctrl+K` / `Cmd+K`：桌面聚焦顶栏搜索；移动端先打开抽屉再聚焦。设置页同样可使用顶栏搜索，不创建第二套搜索实例。
- 使用现有 `GET /api/v1/books?q=...&limit=5&offset=0` 进行全库预览；按当前 API 支持的书名、作者/译者、ISBN 搜索，不承诺尚未支持的标签全文查询。
- 输入防抖 250ms；保留中文输入法 composition 处理。请求取消或序列校验，旧查询结果不可覆盖新查询；空关键词关闭结果，不拉取全库。
- 下拉显示最多 5 本真实书籍：小封面、书名、作者；缺失封面使用现有 BookCover/占位；底部显示全部结果入口和真实总数。
- ↑/↓ 选择、Enter 打开当前结果或全部结果、Escape 关闭结果、点击外部关闭。键盘焦点及下拉位置正确，浮层不被抽屉或顶栏裁切。
- 点击结果进入真实详情路由；点击全部结果或直接回车进入书库并携带 `q`，书库标题下显示可清除的当前查询标签。清除标签只移除 `q`，保留高级筛选与其他可用条件；网络失败显示重试，不伪装成无匹配结果。

## 8. 首页（Dashboard）

目标：以阅读和最近书籍为主，不把系统运行监控或大量统计卡片堆到首页。

```text
首页                                     [＋ 添加书籍]

继续阅读
┌────────┬─────────────────────────┬────────────────┐
│ 封面   │ 书名 / 作者 / 阅读位置   │ 继续阅读       │
│        │ ━━━━━━━━━━━━━━  62%     │                │
└────────┴─────────────────────────┴────────────────┘

最近阅读                                  查看全部 ›
[封面]  [封面]  [封面]  [封面]  [封面]

最近加入                                  查看全部 ›
[封面]  [封面]  [封面]  [封面]  [封面]
```

- PageHeader 提供页面标题和添加书籍主操作；添加行为复用书库中已有真实创建表单及刷新逻辑。
- 继续阅读卡片：桌面横向封面/信息/操作三段；封面建议 150×225，窄屏纵向或紧凑双段。进度、位置及继续阅读目标必须来自真实阅读数据，不从书名、阅读状态或样例推断。
- 最近阅读：复用 BookCard 与横向可滚动书籍集合；最近加入：复用相同展示组件，使用 `sort=createdAt&order=desc` 的现有 API。查看全部进入真实对应页面。
- 当前若只有 Books API，则先交付最近加入与添加入口；未实现的阅读区域可隐藏或显示明确的功能尚未开放提示，不能用“还没有阅读记录”掩盖 API 不存在。
- 真实空书库显示添加第一本书的入口，加载与失败独立处理。不要引入木纹书架或额外装饰材质。
- 阅读时长、年度目标、趋势图放入后续阅读统计模块；系统健康、任务和日志放入设置/管理页面。

## 9. 书库、书架与详情页面模板

### 9.1 书库

- 采用共享 AppShell + `PageHeader`（标题「书库」、真实数量、Soft 添加按钮）+ 页内媒体分段 + 状态/排序 + 筛选/视图/更多 + 图书内容 + Pagination。标题始终位于页面最顶部，所有页面保持一致。
- 保留当前真实创建、查询、编辑、分页、会话失效处理；保留网格和列表，二者共用相同查询条件与结果。
- 媒体分段为「全部书籍 / 实体书 / 电子书」，替代类型下拉或一级导航；阅读状态与排序使用紧凑下拉；网格/列表与封面尺寸放入视图菜单；更多菜单提供刷新与清除全部筛选。
- 搜索由顶栏/抽屉全局搜索驱动；带 `q` 的 URL 进入书库后，在计数旁显示可清除的查询标签，书库页内不出现第二个搜索输入框。
- 高级组合筛选保持现有组件结构、展开方式和交互流程，仅在视觉上紧凑化：位于工具栏下方内联展开，不使用抽屉或弹窗。字段、运算符、值编辑器、添加/删除/清空、固定底部操作和业务校验全部保留。
- 页面查询、筛选、排序、分页和视图状态通过 URL 恢复；修改筛选后回到第一页，取消过期请求。服务端数据保持唯一事实来源。

### 9.2 书架

- 首版普通书架：名称、简介（若模型/API 支持）、真实书籍数量和图书集合。可使用同一个书库内容组件，不另造书目模型。
- 书架管理、创建及编辑复用真实书架接口和表单；待 API 开放后实施。
- 后续智能书架复用经过后端验证的组合筛选模型；合集、自动归类不属于 AppShell 改造任务。

### 9.3 书籍详情

- 使用 `acbooks-book-detail-spec.md` 作为详情专项规范。详情页与书库共享 AppShell，优先独立路由，书目身份始终为真实 `bookId`。
- 宽内容区封面/信息/操作三栏；中等内容区两栏；手机竖屏纵向布局。断点应根据主内容实际可用宽度，不能简单按全屏宽度套三栏。
- 保留书库来源查询及滚动上下文。全局搜索位于顶栏（移动端抽屉），账户入口位于顶栏/抽屉底部并进入设置；退出登录统一在设置页；专项规范中提到的“顶部导航”按新 AppShell 实际结构适配，其他详情内容规则保持不变。
- 详情页已迁移为独立详情路由，本次只调整外壳；必须确保编辑、阅读状态与错误处理不回退；添加和编辑仍可使用 Dialog。

## 10. 设置中心布局

### 10.1 桌面设置模式

从顶栏账户入口进入设置。图标轨与顶栏保持不变，**不叠加第二个永久侧栏**；设置页在 `PageHeader` 下提供页内分类导航（账户 / 外观 / 语言），窄屏显示分类卡片进入子页；返回入口验证为应用内安全业务路由。

```text
┌──────┬──────────────────────────────────────────────┐
│ 首页 │ 设置                                          │
│      │ 管理账户、外观和语言。                        │
│ 图书 │ 账户   外观   语言                            │
│ 库   │ ┌──────────────────────────────────────────┐ │
│      │ │ 账户                                      │ │
│      │ │ 用户名                      admin         │ │
│      │ │ 退出登录                    [退出登录]    │ │
│      │ └──────────────────────────────────────────┘ │
│      │ ┌──────────────────────────────────────────┐ │
│      │ │ 外观 / 语言 …                             │ │
│      │ └──────────────────────────────────────────┘ │
└──────┴──────────────────────────────────────────────┘
```

目标分类（按实际后端能力逐步开放）：

| 分组 | 分类 | 内容 |
| --- | --- | --- |
| 个人设置 | 账户、外观、语言 | 当前账号、退出、已有 ThemeProvider 与 i18n；账号修改待对应接口 |
| 书库与存储 | 存储与书库、元数据来源 | 管理/外部存储、扫描与来源配置；尚未完成则不开放 |
| 数据与连接 | 备份与恢复、设备与同步、协议与集成 | 真实服务完成后实现 OPDS/WebDAV 等，不预设二猫 API |
| 系统 | 任务与日志、关于 | 任务、健康检查、版本/许可及项目链接；按真实能力 |

acbooks 为单用户个人服务，不复制二猫的多用户权限管理、邮件、Kindle、自动化授权等菜单，除非未来另有明确需求。

### 10.2 设置页面内容

- 使用 `SettingsGroup` / `SettingsRow`，顶部标题与简短说明；下方按语义分组。普通行采用左侧名称/说明、右侧控件，窄屏纵向重排。
- 表单不铺满超宽屏；保存按钮、危险操作、加载和失败反馈符合现有规范。危险操作需真实契约和确认，不允许假成功。
- 对已存在的主题与语言功能可直接复用现有状态，不创建额外 API 或本地存储键。账户操作保留现有 logout 与 CSRF 流程。
- 设置页面为独立路由，刷新/前进/返回保持正确选中项。返回入口必须验证是本应用内部允许的业务地址。

### 10.3 移动端设置

- 仍使用全局 AppShell 和抽屉；从抽屉底部账户入口进入设置页，设置页自身提供分类卡片与返回入口，不要求抽屉切换为设置导航；退出登录在设置页账户分组。
- 设置入口/概览按 2 列（窄屏不足则 1 列）展示分类，平板可 3 列；进入具体分类后优先显示分类内容和返回入口，避免每个设置子页面都在顶部堆满所有分类。
- 参考二猫移动设置分类网格，但此处将其限定于设置入口/按需展开，是 acbooks 的适配选择。

## 11. 账户、认证与页面路由

- 账户入口（头像 + 昵称）位于 56px 顶栏右侧（移动端在抽屉底部），点击进入设置；退出登录统一放在设置页账户分组，不再设独立的退出或设置按钮，不将整个头像只变成装饰。
- 复用已实现的 session check、CSRF Token、Cookie、退出 API。将会话与统一失效处理提升到已登录框架或共享 AuthGate；避免每个业务页面重新发起独立认证流程。
- 登录/初始化页、独立开发预览页不嵌入业务 AppShell。后续阅读器等沉浸页面根据需求独立处理，不在本次开发假阅读器。
- 401 会话失效进入登录；403、网络异常及服务端错误按实际语义处理，不把所有异常视为登出。退出成功清理账户关联页面状态和请求，失败显示真实错误；不在 localStorage 保存密码、Cookie 或 CSRF Token。
- 参考路由：`/`（已登录首页；若现有登录流程依赖根路径，先明确迁移）、`/library`、`/library/:bookId`（与详情专项规范及已有路由兼容）、`/shelves`、`/reading/history`、`/reading/statistics`、`/settings` 及其子路由。此清单是目标，不代表全部页面已存在；登录/初始化入口继续遵循当前实现，必要时同步修正跳转及测试。
- 固定导航按真实路由激活；详情进入时书库来源高亮合理；未知路由显示安全的未找到状态或规范回退，不将错误路径当成登录页。

## 13. 开发顺序与范围

1. 确认并行任务及 Git 基线，先明确 AppShell、路由和详情规范之间的边界；保留当前已提交和工作区业务成果。
2. 提升共享已登录 AppShell，统一页面容器、PageHeader、正常/设置导航结构；迁移现有书库，不改变业务逻辑。
3. 实现可用移动抽屉、全局搜索、账户与退出；完成键盘和会话状态处理。
4. 将真实书库、详情页及添加/编辑弹窗接入；按真实 API 调整筛选，确保所有已有功能不回退。
5. 在已有 API 范围内增加首页最近加入、个人主题与语言设置；后续阅读、动态书架、系统设置在独立任务实现对应 API 后再开启。
6. 完成响应式、主题、语言、可访问性和回归测试，提供实际截图与变更报告。

本次不要求开发完整阅读器、阅读同步、书架 CRUD、智能筛选后端、上传扫描、元数据刮削、多用户权限、PWA、OPDS 等。若用户明确授权这些功能，另行设计接口与验收，不混入布局重构。

## 14. 验收标准

### 14.1 视觉与响应式矩阵

| 视口（CSS px） | 必须验证 |
| --- | --- |
| 1920×1080、1440×900 | 80px 图标轨 + 56px 顶栏；书库控件单行；内容无横向滚动 |
| 1280×800、1024×768 | 图标轨与内容不互相挤压；书库分段与控件保持单行，详情按剩余宽度降级 |
| 767×1024、768×1024 | 767 使用抽屉且标题行有菜单触发；768 切换为图标轨，无残留抽屉状态 |
| 390×844、360×800、320×568 | 标题+主操作一行，分段整行，状态/排序整行，筛选/视图/更多成组；无横向溢出 |
| 844×390、667×375 | 抽屉与低高度弹窗可滚动，保存和关闭可达 |
| 200% 浏览器缩放 | 内容重排、标签/菜单可读、所有操作可用 |

至少对 1440×900、1024×768、768×1024、390×844 进行真实截图，包含书库、详情、设置、抽屉打开与搜索结果；深浅主题与中英文均验证。截图来自实际运行及测试数据，不以设计示意图代替验收。

### 14.2 功能与回归

- 登录、会话恢复、退出、401 失效和非认证错误行为不回退；不暴露受保护内容。
- 所有可用导航进入正确页面，浏览器刷新/前进/返回正常；从顶栏/设置入口进入设置后可返回原业务页面。
- 抽屉可打开、关闭、键盘退出、点击遮罩关闭、返回键关闭；切换断点后无遮罩残留和焦点锁定。
- 搜索使用全库真实 API，中文输入法、防抖、请求取消、结果预览、键盘选择和全部结果正确。
- 原有图书添加、查询、详情、编辑、筛选、排序、分页及持久化不回退；列表和网格共用查询，实体/电子视图无重复 Book。
- 未实现页面不展示假数据、假操作和虚假成功提示；已开放页面有加载、空、错误、重试及必要禁用状态。
- 主题和语言切换不重置业务上下文；长名称、动态导航大量条目及窄窗口不破坏框架。

执行当前仓库规定的 `pnpm check` 等命令（以 package.json 和 AGENTS.md 为准），补充共享 AppShell、路由、抽屉、全局搜索、账户入口及现有书库回归测试。若改变真实 API，更新 OpenAPI、生成客户端类型并补后端测试。不得声称未执行的测试已通过。
