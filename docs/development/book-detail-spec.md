# acbooks 图书详情页设计与实现规范

> 状态：待实现；供开发 AI 直接执行。  
> 范围：Web / Windows Web UI（横屏、竖屏、窄窗口）；原生 Android / iOS 仅作布局参考，不在本次实现范围。  
> 参考：二猫书库 ermao-library，main 提交 `21b5715e884fda4375c2621b96f0751f4d542703`（v1.6.3）。  
> acbooks 分析基线：main 提交 `e1ef2b16dfa7262e23c9c53cb496378b1553bc68`。开始开发时重新确认当前分支及已有实现，不回退其他任务的代码。

## 1. 任务目标与执行原则

参考二猫书库的图书详情页布局、信息层级和交互行为，在 acbooks 中实现一套统一的图书详情页。**借鉴布局和交互，不复制其暖色主题、橙色按钮或独立组件体系。**

开发前阅读 `AGENTS.md`、`docs/architecture/system.md`、`docs/development/standards.md`、`docs/development/ui.md`、`docs/development/ui-components.md`、`docs/development/ui-pages.md`、`docs/api/books.md`。涉及接口变更时继续阅读 `backend.md`、`sqlite.md`、`security.md`、`docs/api/conventions.md`。现有规范优先；发现冲突先列出，不擅自改写全局设计规范。

- 复用现有 AppShell、侧边栏、顶部导航、ThemeProvider、I18nProvider、`@acbooks/ui` 与 Lucide 图标。
- 书目身份始终是稳定 `bookId`，实体副本、电子文件、阅读和笔记统一归属于 Book。
- 横竖屏共享同一个页面和状态，不开发两个独立业务页面。
- 首版实现真实详情、元数据编辑、阅读状态更新、返回书库；未完成的阅读器、文件上传、刮削、阅读统计等不提供假功能。
- 本文中的尺寸为 acbooks 建议实施值；若与仓库权威设计令牌、组件尺寸或页面规范冲突，采用仓库规范并记录差异。

### 2.1 Web 详情页

源文件：[book-detail-page.tsx，634–735 行](https://github.com/GMD170629/ermao-library/blob/21b5715e884fda4375c2621b96f0751f4d542703/apps/web/features/books/book-detail-page.tsx#L634-L735)。

| 部位 | 二猫实际实现 | acbooks 借鉴决定 |
| --- | --- | --- |
| 返回 | 顶部返回全部图书，根据来源链接返回 | 保留书库筛选、分页、视图和滚动上下文 |
| 容器 | 圆角 22px，内边距 20/24px，栏间距 24px | 使用现有面板与间距令牌；AppShell 内容区已有面板，避免再堆多层装饰卡片 |
| 封面 | 2:3，窄屏 96px，sm 起 150px，上限 150px；窄屏居中、lg 起靠左 | 宽屏 150×225px；紧凑竖屏居中 132×198px，后者参考原生端 |
| 信息 | 标题最多 2 行，作者、系列、标签、简介、阅读进度、当前位置 | 书名、作者/译者、ISBN、标签、书架、简介；真实阅读进度以后接入 |
| 响应式 | `lg:grid-cols-[150px_minmax(0,1fr)_230px]`；操作区 `lg:col-start-2 xl:col-start-3`，xl 起纵向且底对齐 | 明确宽屏三栏、中屏两栏、窄屏纵向；避免中屏出现空的第三列 |
| 主操作 | 有对应可读资源时，开始/继续阅读或收听；48px 高 | 使用 acbooks 规定的 44px lg Soft 按钮；没有阅读能力时用编辑书籍 |
| 次操作 | 阅读状态选择器和 Ellipsis 更多菜单；横向组合 | 阅读状态独立可见；更多操作收纳到菜单 |
| 简介 | `whitespace-pre-line`、默认 3 行，展开后取消截断 | 保留换行，真实测量溢出才显示展开按钮 |
| 内容区 | 按选中资源切换 `ResourceDetailView` / `BookContentBrowser` | 不引入来源目录树；先按 BookCopy / BookFile 显示真实关联 |

注意：二猫 Tailwind 配置没有覆盖默认断点。其 Web 实现依赖 `sm/md/lg/xl`（640/768/1024/1280px），而不是通过设备方向强制决定布局。它在 lg 到 xl 之间已声明三列，但操作区仍在第二列；本规范选择真正的两栏作为过渡，不照搬该细节。

## 3. acbooks 当前源码与接口边界

当前已提交基线的书库入口为 `apps/acbooks-web/src/library/LibraryPage.tsx`，公共布局为 `layout/AppShell.tsx`。`BookCard.tsx` / `BookListItem.tsx` 仍从 `sample-books.ts` 取展示类型；正式详情页尚未实现。当前 `App.tsx` 将 `/library` 及其子路径交给 LibraryPage，新增详情路由时必须区分列表路径与详情路径。

后端已有：

| 接口 | 用途 |
| --- | --- |
| `GET /api/v1/books/{bookId}` | 获取 BookDetail |
| `PATCH /api/v1/books/{bookId}` | 更新书目字段、阅读状态和关联名称 |
| `GET /api/v1/books` | 返回书库及支持的筛选结果 |

详情真实字段：`id`、`title`、`authors[]`、`translators[]`、`isbn`、`readingStatus`、`tags[]`、`shelves[]`、`description`、`identifiers[]`、`copies[]`、`files[]`、`copyCount`、`fileCount`、`formats[]`、`createdAt`、`updatedAt`。

- 副本：`id`、`locationId`、`locationName`、`acquiredAt`、`note`。
- 文件：`id`、`format`、`fileStatus`、`sizeBytes`。当前没有文件名、下载 URL 或封面 URL；不展示内部路径，也不猜测文件名。
- 阅读状态真实取值 `unread / reading / done`，分别显示未读 / 在读 / 已读；和阅读百分比不同。
- 目前没有真实阅读进度、封面读取/上传、文件管理、实体副本管理、书架查询、删除书目的接口。`shelves` 返回名称而非 UUID，不能凭名称构造 `shelfId`。
- 复用 `packages/acbooks-api-client/schema.d.ts` 自动生成类型；如果已有联调代码，以当前实际源码为准，不另造 DTO 或通用请求模块。

依据：[acbooks Books API](https://github.com/helloactop/acbooks/blob/e1ef2b16dfa7262e23c9c53cb496378b1553bc68/docs/api/books.md)、[后端 schemas.py](https://github.com/helloactop/acbooks/blob/e1ef2b16dfa7262e23c9c53cb496378b1553bc68/apps/acbooks-server/app/modules/books/schemas.py)、[AppShell.tsx](https://github.com/helloactop/acbooks/blob/e1ef2b16dfa7262e23c9c53cb496378b1553bc68/apps/acbooks-web/src/layout/AppShell.tsx)。

## 4. 页面整体结构

建议详情路径 `/library/books/:bookId`（若当前代码已定义统一详情路由则复用）。从书卡封面/书名及列表书名进入详情，使用真正的链接或可访问的路由入口，不能用只响应鼠标的 div。

```
AppShell（沿用现有布局）
└─ BookDetailPage
   ├─ 返回书库 / 面包屑
   ├─ BookDetailHeader
   │  ├─ BookCover
   │  ├─ BookIdentity（书名、作者、译者、ISBN、标签、书架）
   │  ├─ BookDescription（位置随宽度调整）
   │  └─ BookActions（主按钮、阅读状态、更多）
   ├─ DetailTabs（信息 / 阅读 / 笔记）
   └─ TabPanel
      ├─ 信息：电子文件、实体副本、书目补充信息
      ├─ 阅读：进度、统计、阅读记录（后续实现）
      └─ 笔记：书签、高亮、笔记（后续实现）
```

注：分页最终名称和组件以仓库 `ui-pages.md` 定义为准；如项目当前使用其他命名（如阅读相关记录与高亮统一命名），沿用既定术语。切换分页只更换下方内容，不更换书籍头部。首版未接入的分页可禁用或展示明确的未开放说明，不做伪造空数据。

## 5. 横屏、竖屏及宽度自适应规范

以详情内容容器的实际可用宽度 W（不包含侧边栏及外部内边距）判断布局，优先使用 CSS Container Queries；现有工程已有同类响应式机制时复用。屏幕方向仅作为测试场景，不作为唯一断点。用户调整窗口、展开/收起侧栏、旋转屏幕时应自然重排，不卸载表单、不丢失状态。

| 内容宽度 W | 布局 | 封面 | 操作区 |
| --- | --- | --- | --- |
| ≥ 1000px | 三栏宽屏 | 150×225px | 230px 宽，纵向排列，底部对齐 |
| 640–999px | 两栏中屏 | 132–150px 宽，2:3 | 信息区下方横向排列，空间不足换行 |
| < 640px | 单列竖屏 | 132×198px，居中；极窄可减至 112×168px | 主按钮全宽；状态与更多同一行，简介在下方 |

这些断点为本任务建议，不是二猫或 acbooks 已有强制断点。沿用 AppShell 已有的移动端隐藏/收起侧栏策略；不要再建立第二个全局侧栏。使用 `min-width: 0`、长文字换行、响应式间距，禁止横向滚动来容纳固定栏。

### 5.1 横屏 / 桌面三栏

```
‹ 全部书籍
┌───────────────────────────────────────────────────────────┐
│ ┌──────────┐   书名（允许长标题换行）                   │
│ │          │   作者 · 译者                         ┌─────┐│
│ │  封面    │   ISBN                                │     ││
│ │ 150×225  │   标签 / 书架                         │编辑 ││
│ │          │   简介正文（默认三行）                 └─────┘│
│ └──────────┘   展开简介                     [在读 ⌄] [···]│
└───────────────────────────────────────────────────────────┘
信息  /  阅读  /  笔记
─────────────────────────────────────────────────────────────
实体副本                          电子文件
真实关联记录                     真实关联记录
```

- 内容区沿用现有桌面 24px 内边距；头部三栏 `150px minmax(0,1fr) 230px`，栏间距 24px。需要单独面板时用现有圆角 `rounded-panel`、语义边框，避免重复包裹 AppShell 已提供的白色面板。
- 封面左对齐、顶对齐；比例固定 2:3，不拉伸或裁掉书名。信息从标题向下排列，主按钮和次操作纵向组合，操作组与标题顶部对齐；简介展开时操作区保持位置稳定，不随头部增高上下移动。
- 中间区域简介最大阅读宽度建议 65–75 个拉丁字符的等效长度（可通过 `max-width` 限制）；不能因为超宽显示器而把文字拉成一条很长的行。
- 展开简介时头部自然增高，不让操作按钮跳出屏幕或与简介覆盖；整页使用 AppShell 已有主内容滚动容器。
- 下方信息区可并排展示副本与文件（内容宽度足够时），否则纵向展示；两区没有数据时仍有自己的真实空状态。

### 5.2 中等宽度 / 平板 / 手机横屏

```
‹ 全部书籍
┌──────────┐  书名
│  封面    │  作者 / 译者 / ISBN
│ 132–150  │  标签 / 书架
└──────────┘  [编辑书籍] [在读 ⌄] [···]
简介（最多三行）                  展开
信息  /  阅读  /  笔记
内容区（按宽度单列或双列）
```

- 两栏 `132–150px minmax(0,1fr)`；间距 16–24px。
- 操作区不留空的第三列；主按钮、状态、更多可横排，放不下时换行，不挤压文字。
- 简介可移动至两栏下方，使用整行宽度，保证可读性。
- 手机横屏即使有宽度，也可能只有 360–430px 高。不能采用固定全屏高度的头部或固定底部操作区占满屏幕。允许自然纵向滚动；弹窗 Header/Footer 之外的 Body 可滚动。
- 如果实际容器宽度不足 640px，即使设备处于横屏仍使用单列。侧栏折叠、浏览器缩放和大字号下同理。

### 5.3 竖屏 / 手机

```
‹ 全部书籍
              ┌──────────┐
              │          │
              │  封面    │
              │ 132×198  │
              └──────────┘
                 书名
            作者 · 译者
                 ISBN
             标签 / 书架
          [     编辑书籍     ]
          [    未读 ⌄   ] [···]

内容简介正文（默认三行）
                         展开简介
─────────────────────────────────
      信息      阅读      笔记
实体副本
电子文件
```

- 页面内边距使用现有移动端 16px；封面、书名、作者和标签组居中，简介及下方列表左对齐。
- 标题允许最多 3 行；长标题不得撑破容器，完整标题可由可访问名称及实际详情文本取得。作者、译者、标签可自然折行。
- 主按钮全宽，高 44px；次操作一行，阅读状态选择器占剩余空间，更多操作最小触控区 44×44px。
- 简介位于操作区之后（参考二猫 Android/iOS），不因长简介将主按钮推到很下面。
- 选项分页在窄屏应可触达，避免三个 Tab 被截断或相互覆盖；内容按单列展开，文件/副本以紧凑行展示。
- 360px 或更窄、200% 字号时以内容可读、可操作优先，允许纵向增长。无水平溢出，不缩小字号以强塞内容。

## 6. 书目信息区（字段和样式）

| 顺序 | 字段 | 展示要求 |
| --- | --- | --- |
| 1 | 书名 | 页面唯一 h1；桌面建议 28–32px、移动 24–28px，采用现有字号规范；桌面最多 2 行、竖屏最多 3 行 |
| 2 | 作者 | `authors[]`，完整展示或合理换行；无作者则不留空行 |
| 3 | 译者 | `translators[]`，独立于作者，避免误将译者显示为作者 |
| 4 | ISBN | 可选、支持复制真实值，不显示假 ISBN |
| 5 | 标签 / 书架 | 用现有中性标签样式展示真实名称，允许换行；不可将 EPUB/PDF/实体书混入业务 tags |
| 6 | 简介 | 按第 7 节实现 |

可点击规则：作者可按 `q` 跳转到当前支持的关键词查询（须说明不是精确作者筛选）；标签可按 `tag` 筛选；书架只有获取真实 `shelfId` 或明确支持名称筛选的接口后才可跳转，否则只显示名称。不要构造虚假的筛选链接。

封面：现有 API 不返回可访问封面 URL，首版使用统一、确定性占位封面（书名与作者、对比度合格），可复用书卡封面表现；不得随意联网获取或以封面缺失推断无电子书。以后封面接口完善后切换真实图片并处理加载失败。无作者时不要生成虚构作者。

## 7. 内容简介（必须实现的细节）

参考二猫 Web 的 `line-clamp-3`、Android 的真实溢出测量及原生端纯文本处理。

1. 仅使用 `BookDetail.description`；不读取第一个电子文件的简介覆盖整书。保留段落换行，去除首尾多余空白，不显示 HTML 标签。以纯文本安全渲染；禁止未经安全清理的 `dangerouslySetInnerHTML`。
2. 桌面置于中间信息栏，手机/中等宽度置于操作区之后或两栏下方，均左对齐。
3. 默认最多 3 行，使用标准 `line-clamp-3`；行高建议 1.65–1.75，颜色 `text-muted-foreground`，字号使用正文令牌。
4. 实际发生截断时才显示「展开简介」。通过测量折叠态溢出（例如独立测量元素或可靠的 scrollHeight/clientHeight 对比）判断；监听容器尺寸、文本变化、字体加载。禁止按字符数猜测行数。
5. 展开后取消行数限制，按钮改为「收起简介」；再次点击恢复 3 行。展开状态按 bookId 保存，切换分页、旋转屏幕和刷新详情不重置；切换到新书默认折叠。
6. 使用文本/ghost 轻量按钮和 ChevronDown/ChevronUp（若现有规范允许），设置 `aria-expanded`、`aria-controls`。展开不使用新的 Dialog，不自动跳转页面或移动焦点；展开、收起后保持触发按钮附近的阅读位置。
7. 没有简介显示简短的「暂无简介」或按现有页面规范隐藏空区域，不保留大块占位，不把未加载误作无简介。短简介不显示展开按钮。
8. 保存编辑后以服务端返回的新文本更新，重新判断溢出；避免快速切换书籍时旧请求覆盖当前简介。

## 8. 操作区规范

### 8.1 主按钮

- 首版：`编辑书籍`，使用现有 `Button variant="soft" size="lg"`、Pencil 图标，真实打开编辑弹窗。
- 后续：存在真实可读资源、阅读入口已实现且目标可用时，改为「开始阅读 / 继续阅读」。每页只保留一个最重要的 Soft 主按钮，编辑移至更多菜单。
- 不从阅读状态 `reading` 猜测阅读百分比，不选择第一个文件假装恢复上次阅读位置。暂无阅读能力时不显示无效阅读主按钮。

### 8.2 阅读状态

使用规范化 Select 选择未读 / 在读 / 已读；回填 `readingStatus`，调用 `PATCH /api/v1/books/{bookId}` 仅提交变更字段。保存中禁用重复操作；成功更新详情与书库缓存，失败保留原值并提示。不要套用二猫的“已读即进度 100%”业务逻辑或自动清除定位；这涉及 acbooks 后续阅读模型规则。

### 8.3 更多操作

使用 Lucide Ellipsis（或项目已有规定的同类图标）及符合规范的 DropdownMenu。首版只开放真实可执行的项目，例如编辑书籍、复制 ISBN（有值时）。主按钮已是编辑时可不重复菜单项。加入书架通过现有 PATCH 名称数组操作时须保留原有项；没有可靠交互或契约时不开放。元数据识别、上传、下载、删除等未实现操作隐藏或明确禁用。禁止调用当前返回 405 的删除接口，禁止通过直接删除 SQLite 数据模拟删除。

菜单支持键盘、Esc、点击外部关闭、焦点返回。后续危险操作必须使用规范化 AlertDialog 且明确作用范围，不让整书菜单作用于单个文件。

## 9. 下方分页与真实数据展示

采用仓库规定的 Tabs 或 SegmentedControl（按语义与现有 `ui-pages.md` 选择），不是新造一套胶囊样式。页签及内容共享同一 BookDetail，不因数量分裂成不同书籍详情。

### 信息

- 实体副本：展示实际数量、存放位置、取得时间（有值时）、备注（有值时）；位置为空显示未设置，不猜测位置。无副本显示「暂无实体副本」。当前只读。
- 电子文件：展示实际格式、大小、存在/缺失状态；当前 API 无文件名，使用格式及必要的区分信息，不生成假文件名。文件缺失不自动删除书目或阅读历史。无文件显示「暂无电子文件」。当前只读。
- 补充信息：仅在需要时显示标识符、书目创建和更新时间；时间按 locale 和用户时区格式化。不要重复堆叠顶部已展示的每个字段。
- 内容结构以分组标题、列表和细分隔线为主；桌面有空间时可以两组并排，手机单列。不要求每一行都套卡片。

### 阅读 / 笔记

后续阅读页展示真正的阅读会话、统计、进度与当前文件；笔记页展示书签、高亮和笔记。当前接口未实现，首版按页面规范隐藏未开放入口或展示明确的未开放说明，不把尚未接入的页面描述为“已有 0 条阅读记录”。不得把虚构进度条放进头部或文件行。

## 10. 编辑书籍弹窗

参考二猫固定头尾、滚动表单、响应式双列的实现。复用添加书籍的 BookForm（如果另一任务已实现，直接共用），编辑与添加只在初始值和提交接口上不同。

- 桌面居中 Dialog，复杂表单建议最大宽 640px，圆角 24px（以项目规范为准）；Header/Body/Footer 三段；Header 含标题与关闭按钮，Body 独立纵向滚动，Footer 固定。桌面双列、窄屏单列；手机横屏低高度时限制整体高度至视口以内，保留可见的取消/保存，表单滚动。
- 字段：书名（必填）、作者（多值）、译者（多值）、ISBN（可选）、阅读状态、标签（多值）、书架（多值）、简介（多行独立字段）。标题、简介和多值字段按实际空间跨列。封面上传及 ISBN 自动填充尚无接口，首版不提供假按钮。
- 作者、译者、标签、书架使用公共 `MultiValueInput`，直接维护字符串数组：回车或逗号添加、退格删除末项、标签 × 移除；不再把数组拼接为逗号文本后再拆分。简介使用公共 `Textarea`，阅读状态使用公共 `Select`。
- 使用 `Field`、`Input` 及公共 Select/Combobox/Dialog；公共组件缺少时按现有 Radix/shadcn、Tailwind、Lucide 规范最小补齐，导出并测试；禁止复制二猫的私有组件体系。
- 输入初值来自真实详情；遵循 BookUpdate 契约：未修改字段不提交；清空简介、ISBN 使用 null；清空作者/译者/标签/书架使用空数组；其他字段禁止传 null；空 PATCH 不提交。作者等列表整体替换，不误删未编辑项。
- 保存使用 `PATCH /api/v1/books/{bookId}`，Cookie 写入需要 CSRF；真实成功后关闭弹窗、更新详情及列表。失败保留输入，展示本地化错误；提交期间防止重复保存；有关闭按钮、取消、Esc 或遮罩关闭时，如存在未保存修改则先确认“放弃修改 / 继续编辑”。
- Header 明确标题，Footer 取消 Ghost / 保存 Default（按 `ui-pages.md` 既定编辑弹窗规则）；避免在弹窗使用与主页面冲突的第二套视觉体系。

## 11. 组件划分与工程实现

建议目录（不是强制替换现有目录）：

```
apps/acbooks-web/src/library/
  BookDetailPage.tsx          # 路由、鉴权、数据和页面状态
  BookDetailHeader.tsx        # 响应式封面、信息和动作组
  BookDescription.tsx         # 三行截断、真实溢出测量、展开状态
  BookDetailActions.tsx       # 阅读状态、编辑、更多菜单
  BookDetailTabs.tsx          # 内容分页
  BookInfoPanel.tsx           # 文件、副本和补充信息
  BookEditDialog.tsx          # 复用 BookForm
  BookForm.tsx               # 添加/编辑共用，若已有则复用
  books-api.ts               # 已有联调 API 层优先复用
```

通用控件放 `packages/acbooks-ui`；业务组合组件放 Web library 模块。不要为单一页面引入另一套 CSS 变量、UI 框架或复杂状态管理。共用封面表现时不依赖 `sample-books.ts` 的假数据类型。

- 配色全部取语义令牌：`frame`、`background`、`surface`、`foreground`、`muted-foreground`、`border`、`control-border`、`accent-soft`、`accent-border`、`accent-text`、`ring` 等。
- 使用现有 22px 面板圆角、10px 控件圆角、按钮/输入框/图标规范。主按钮 Soft 的字重、边框和对比度遵守 v3；不得使用二猫的橙色实心按钮。
- 所有用户文案、错误、aria-label、Tooltip 和日期格式均支持简体中文与英文；用户的书名、作者和简介不翻译。
- 尊重 `prefers-reduced-motion`，不使用大面积布局动画，不在详情页增加新的视觉材质、渐变背景或复杂阴影。

## 12. 路由、请求、状态和返回行为

- 所有详情必须处于认证保护下；直接打开详情 URL 与刷新均能正确加载。复用现有会话机制，401 返回登录入口，403/404/网络错误分别处理，不能一律显示无书籍。
- 通过生成的 API 类型与真实 `bookId` 请求数据；快速打开不同书籍、切换账号或离开页面时取消或忽略旧响应，避免串书。
- 加载态与无数据状态分开，保留稳定布局；请求失败提供重试。编辑保存成功刷新列表缓存，不要重复插入新 Book。
- 从书库进入详情前保存当前查询、过滤、排序、分页、网格/列表、滚动位置；返回后恢复。可优先使用已有 URL/历史状态，不持久化认证信息。直接打开详情且没有返回上下文时回到 `/library`。
- 同一本书在横屏/竖屏切换、窗口缩放、主题切换、语言切换时保留当前分页、简介展开、编辑草稿和滚动上下文；不要根据媒体查询创建两个独立页面实例。

## 13. 验收清单

### 视觉与响应式

| 测试视口（CSS px，建议） | 预期 |

| 1440×900、1280×800 | 内容宽度足够时三栏，否则正确两栏；AppShell 保留 |

每种典型宽窄布局检查浅色与深色、中英文；至少检查 1440×900、390×844、844×390 三种真实截图。截图应使用测试书籍（长书名、多个作者/译者、长简介、缺失简介、缺失封面、零/多副本和文件）；不要用样例数据替代正式页面的数据源。

### 功能

- 网格/列表打开同一 BookDetail，直接访问详情路由、返回书库和重新加载正常。
- 简介短文无展开按钮，长文折叠三行、展开和收起正常，空简介处理正确；尺寸改变后溢出判断正确。
- 阅读状态 PATCH 与编辑 PATCH 成功、失败、重复提交和 401/403/404 情况正确；实际保存数据刷新后仍存在。
- 标签和作者跳转使用实际契约，未实现的书架 ID 或精确作者筛选不伪造；真实媒体格式与业务标签区分。
- 键盘导航、焦点返回、Dialog/DropdownMenu、中文输入法、移动端触控、长文本和深浅主题正确。
- 阅读/笔记/文件管理等未开放功能没有伪造数据及虚假成功。

执行当前仓库规定的前端检查（例如 `pnpm check`，以 package.json 为准）；为详情路由、数据加载、简介展开、编辑和状态更新补充测试。如有接口修改，更新真实 OpenAPI 并重新生成客户端类型、补充后端测试。实际运行结果如实报告，不能用编译通过替代视觉和联调验收。
